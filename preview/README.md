# Prune · локальный просмотр отчётов

Главная страница `preview/index.html` теперь использует Atlas — основной
интерактивный просмотрщик. Он работает в браузере, читает локальный JSON-отчёт
и ничего не сканирует, не удаляет и не меняет на диске. Это ещё не Tauri GUI и
не готовый desktop-инсталлятор.

## Открыть

Можно открыть `preview/index.html` напрямую. Если браузер ограничивает локальные
ресурсы, из корня репозитория запустите:

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory preview
```

Затем откройте <http://127.0.0.1:8080>. Это локальный статический сервер без API
записи. Установка пакетов и внешние сетевые ресурсы не нужны.

## Использование и конфиденциальность

- При запуске открыт **вымышленный** отчёт с примерами путей `/example`; это не
  сканирование вашего компьютера.
- «Открыть отчёт» загружает выбранный JSON только в память текущей вкладки.
  Отчёт не отправляется в сеть; после перезагрузки снова появится демо.
- Для получения реального отчёта нужен установленный CLI: выполните
  `prune scan --json > report.json`, затем откройте этот файл. CLI запускает
  read-only сканирование. Просмотрщик не запускает команды за вас.
- Импортированный JSON может содержать личные пути. Не публикуйте его или
  скриншоты без проверки.
- Поиск, категории, уровень риска и сортировка помогают найти записи. Выбор
  показывает описание, размер, риск и способ повторного создания.
- На клавиатуре: выберите запись, нажмите «Сведения» и затем «Вернуться к
  записи». Для полного списка используйте поиск или страницы.
- При ошибке импорта предыдущий отчёт остаётся на экране. Ошибки и сведения о
  полноте отображаются отдельно.

## Ограничения данных

Поддерживаются `ScanReport` с `schema_version: 1` и `schema_version: 2`. Предел файла — 5 МиБ;
максимум 10 000 записей и 1 000 ошибок. Неизвестные категории, риск или способ
повторного создания отклоняются.

Для v1 полнота определяется консервативно: `cancelled` имеет приоритет; ошибки,
подавленные ошибки, `partial: true` или неполные записи означают частичный
результат. Без признака `partial` и без ошибок состояние неизвестно; только
явное `partial: false` без таких признаков означает «полный по данным отчёта».
Для v2 канонично поле `completeness` (`complete`, `partial`, `cancelled`,
`unknown`). Если присутствуют старые флаги, `partial` должно быть true только
для `partial`, а `cancelled` — только для `cancelled`; `partial` и `cancelled`
не могут быть true одновременно. Состояние `cancelled` сохраняется при наличии
ошибок или неполных записей. `unknown` остаётся неизвестным даже при наличии
диагностик, но не может сопровождаться положительными старыми флагами. `complete`
не допускает старых флагов true, ошибок, подавленных ошибок или неполных записей.

Числа v1 принимаются как JSON numbers только в диапазоне безопасных целых
JavaScript. В v2 поля u64 принимаются как безопасные JSON numbers или канонические
десятичные строки до `18446744073709551615`; нормализованные значения v2 остаются
точными. V1 не принимает числовые строки. Переполнение сумм v1 отклоняется; суммы
v2 считаются точно. Отображение больших размеров округляется только для чтения,
а доли диаграмм рассчитываются в базисных пунктах.

У v2 есть ограниченная область сканирования: тип корня, категории, максимальный
риск, минимальный размер и digest набора правил. `comparable` всегда false:
экспорт не содержит приватной идентичности корня и не доказывает, что два файла
отчёта относятся к одному пользователю или компьютеру. Просмотрщик не сравнивает
отчёты и не создаёт хеши путей. Категории и `max_risk` должны принадлежать
соответствующим enum; категории уникальны и отсортированы. `max_risk` —
включительный верхний предел риска; `null` означает, что предел не задан. Сырой
путь корня не включается. В v1 без scope область неизвестна. `min_size_bytes`
следует правилам числового представления v2 выше.

В finding поле `path_encoding` (необязательное в v2, `utf8` по умолчанию в обеих
версиях) принимает `utf8` или `lossy_utf8`. При `lossy_utf8`
просмотрщик явно предупреждает, что отображённая строка пути может не совпадать с
исходными POSIX-байтами и не является точным путём для файловых операций.

«Суммарный размер» — логическая сумма размеров из отчёта, а не прогноз
освобождённого места; жёсткие ссылки могут учитываться повторно. Уровень риска —
оценка правила, не разрешение на удаление. Повторное создание данных не
гарантирует возврат прежнего содержимого.

CLI может маскировать известный путь к домашней папке при создании JSON:

```bash
prune scan --json --redact-home > report.json
```

Маскирование заменяет распознанные префиксы домашнего пути в строковых значениях
на `~`. Это не полная анонимизация. Проверьте файл вручную перед отправкой.

## Проверки

```sh
node --test preview/*.test.mjs preview/legacy/*.test.mjs preview/concepts/focus/*.test.mjs
node --check preview/app.js
node --check preview/report.js
cargo build --workspace --release --locked
node scripts/check-report-contract.mjs
```

Тесты Node проверяют обработчики и DOM-модель, но не заменяют ручную проверку
скринридером, увеличением 200% и на реальных размерах экранов.

`scripts/check-report-contract.mjs` запускает read-only CLI scan на одноразовой
фикстуре в домашней папке и проверяет исходный и маскированный schema v2 отчёты
парсером просмотрщика. Скрипт удаляет только созданную им фикстуру.
